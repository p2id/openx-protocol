The idea

Don't start with software. Start with a problem.

Most products begin with an idea and search for a reason to exist. OpenX reverses the process: observe friction first, then build around evidence.

01

Service → Software

Find repeatable human work, map the process, and turn the automatable parts into a useful digital tool.

02

Problem → Tool

Start from a recurring user or developer problem and build the smallest complete solution around it.

03

Software → Alternative

Build independent alternatives where privacy, freedom, portability, interoperability, or control can be improved.

Priority principles

Build software people can control.

The protocol puts privacy and freedom ahead of convenience when designing the product, architecture, and user experience.

01 / PRIVACY

Privacy first.

Minimize collection, reduce tracking, prefer local processing, and make data handling understandable.

02 / FREEDOM

Freedom first.

Reduce unnecessary lock-in and favor portable data, open standards, self-hosting, and user control.

03 / EVIDENCE

Evidence over assumption.

Observe the problem, test the hypothesis, measure real use, and document what changes.

04 / OPEN

Open by default.

Share the reasoning, architecture, documentation, and implementation whenever there is no legitimate reason to restrict them.

05 / SIMPLE

Smallest complete solution.

Build the smallest product that can actually solve the core problem instead of collecting speculative features.

06 / SECURE

Security by design.

Consider security from discovery through deployment rather than treating it as a final layer.
